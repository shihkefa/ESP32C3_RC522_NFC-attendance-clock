# ESP32C3_RC522_NFC-attendance-clock
NFC-attendance-clock


# 從零開始 DIY 一台具備 Web 管理介面的 NFC 打卡鐘

公司原本需要一套簡單的上下班打卡設備，但市面上的商用打卡鐘除了價格不低，後續管理方式、資料格式與功能通常也不容易自行調整。因此，我決定使用 ESP32、RC522 與 ESPHome，自己製作一台可以獨立運作的 NFC 打卡鐘。

最初的構想只是「刷卡後記錄時間」，實際製作後陸續加入員工管理、上下班模式、加班打卡、Excel 匯出、每日備註、離線使用、資料備份及 Web 管理介面，最後完成了一套不依賴 Home Assistant 也能獨立使用的出勤系統。

## 為什麼選擇 ESP32-C3 與 RC522？

主控制器使用 ESP32-C3，主要原因是價格低、體積小，而且已經內建 Wi-Fi。打卡資料、員工資料與管理網頁都可以直接保存在主機中，不需要另外準備電腦或伺服器。

讀卡器則選擇 RC522。它價格便宜、取得容易，使用 SPI 與 ESP32 連接，適合讀取常見的 13.56 MHz MIFARE 卡片或感應扣。

這套設備主要使用以下零件：

* ESP32-C3 開發板
* RC522 感應讀卡器
* DS3231 備用時鐘模組
* 3.3V 有源蜂鳴器
* 四顆打卡模式按鈕
* ESP32-C3 開發板上的 RGB LED
* 5V USB 電源

一開始我曾考慮加入 OLED 螢幕與有線網路，但考量成本、接線數量與實際需求，最後取消螢幕並改用 Wi-Fi。設備狀態直接透過燈號與蜂鳴器提示，詳細資料則在手機或電腦的管理網頁查看。

## 四種打卡模式

一般打卡鐘通常只有上班與下班，但實際使用時還需要記錄加班，因此這台打卡鐘設計了四顆實體按鈕：

* 上班
* 下班
* 加班上班
* 加班下班

按下其中一顆按鈕後，設備會維持在該打卡模式，接下來所有員工刷卡都會依照目前模式保存。

為了避免員工刷錯，內建 RGB LED 會使用不同顏色顯示目前狀態：

* 綠燈：上班
* 紅燈：下班
* 黃燈：加班上班
* 藍燈：加班下班
* 七彩燈：等待登記新卡
* 橘燈閃爍：Wi-Fi 尚未連線

系統每天凌晨 00:00 會自動切換為上班模式，下午 14:00 自動切換為下班模式。管理員也可以透過 Web 管理介面遠端切換，不一定要走到打卡鐘旁邊按按鈕。

## 刷卡成功與失敗提示

員工將已登記的卡片靠近 RC522 後，如果時間與資料都正常，蜂鳴器會叫一聲，代表本次打卡已成功保存。

如果蜂鳴器連續叫三聲，則表示本次操作沒有成功，可能原因包括：

* 卡片尚未登記
* 卡片已綁定其他員工
* 系統時間尚未準備完成
* 打卡資料寫入失敗
* 登記新卡時發現重複卡號

這樣即使沒有螢幕，員工也能透過聲音立即判斷刷卡結果。

## 第一次使用可透過 AP 模式配網

為了讓一般使用者不需要修改程式，設備第一次開機後，如果找不到已設定的 Wi-Fi，會自動開啟名為 `NFC-Clock-Fallback` 的配網熱點。

使用者只要依照下列步驟設定：

1. 將打卡鐘接上 5V USB 電源。
2. 等待約一分鐘，直到橘燈持續閃爍。
3. 使用手機搜尋並連接 `NFC-Clock-Fallback`。
4. 如果手機提示「這個 Wi-Fi 沒有網際網路」，選擇仍要連線或保持連線。
5. 等待配網頁自動彈出。
6. 如果沒有自動出現，使用瀏覽器開啟 `http://192.168.4.1/`。
7. 選擇公司的 2.4 GHz Wi-Fi，輸入正確密碼並儲存。
8. 讓手機重新連回公司 Wi-Fi，再開啟打卡鐘管理網頁。

同一個區域網路內，可以使用固定名稱：

`http://nfc-attendance-clock.local/attendance/`

如果部分路由器或電腦不支援 mDNS，也可以直接使用設備取得的 IP 位址登入。

## 不依賴 Home Assistant 的 Web 管理介面

雖然設備使用 ESPHome 開發，也可以連接 Home Assistant，但日常打卡與管理功能並不依賴 Home Assistant。

ESP32 本身提供完整的 Web 管理介面，管理員可以使用手機、平板或電腦完成以下操作：

* 查看設備目前時間
* 查看 Wi-Fi 名稱、網路狀態及 IP 位址
* 遠端切換四種打卡模式
* 新增、修改及刪除員工
* 登記員工感應卡
* 搜尋刷卡紀錄
* 填寫每日請假或出勤備註
* 下載近兩個月的 Excel 彙總表
* 修改管理員密碼
* 手動校正時間
* 匯出及匯入完整備份
* 清除全部刷卡紀錄

目前最多可管理100位員工及256筆每日備註。管理頁會顯示最近100筆刷卡資料，而設備內保存最近兩個日曆月的完整打卡紀錄。

## Excel 出勤彙總

打卡資料不只可以在網頁查看，也能直接下載成 Excel 檔案。

彙總表會依照以下欄位整理：

* 日期
* 員工編號
* 員工姓名
* 上班時間
* 下班時間
* 加班上班時間
* 加班下班時間
* 每日備註

除了全部員工的總表，每位員工也會建立獨立分頁，分頁名稱使用「工號_姓名」，方便管理員查詢、列印或交給會計進一步整理。

## 為什麼後來加入 DS3231？

最初設備只依靠 SNTP 網路校時，但實際測試發現，某些網路環境可能需要等待一段時間才能取得正確時間。在沒有外網的情況下，設備甚至可能暫時無法記錄刷卡資料。

因此後來加入帶有 CR2032 電池的 DS3231 備用時鐘。

設備重新開機時會先讀取 DS3231，所以即使外網中斷，也能快速取得時間並繼續刷卡。網路恢復後再透過 SNTP 自動校正，並將正確時間寫回 DS3231。

管理員也可以在內網管理頁面手動設定日期與時間。手動設定後，本次開機期間會優先使用管理員設定的時間，避免立刻又被網路時間覆蓋。

## 解決斷電後資料消失的問題

製作過程中曾經遇到一個嚴重問題：員工與卡片登記完成後，只要設備斷電重啟，資料就會消失。

後來重新調整 ESP32 的儲存方式與 Flash 分割區，將員工、卡號、備註及刷卡紀錄寫入非揮發性儲存空間。修正後即使拔除電源，重新開機後資料仍然存在。

系統也加入完整 JSON 備份功能。更換開發板或重新刷入韌體前，可以先匯出備份，再將資料匯入新設備，不需要重新登記所有員工與卡片。

## 製作過程中遇到的問題

這個專案真正困難的地方，其實不是讓 RC522 讀到卡號，而是如何讓它變成一台能長期使用的設備。

開發過程中曾經遇到：

* 中文姓名在網頁顯示為 `undefined`
* 刷卡有反應，但沒有寫入紀錄
* 斷電後員工資料消失
* 工號或卡號可能重複登記
* 員工刪除後，原有備註無法刪除
* Web 首頁可以開啟，但管理頁沒有回應
* ESP32 分割區位置未對齊而無法編譯
* 網路時間尚未同步，導致刷卡失敗
* mDNS 名稱在部分網路環境無法解析
* 管理頁資料太多，畫面過長而不方便操作

這些問題陸續修正後，管理介面改為分頁顯示，並加入搜尋、分頁、重複檢查、資料備份及離線時間維持等功能。

## 使用上的限制

RC522 主要是讀取卡片 UID，因此適合一般公司內部出勤紀錄，但它並不是高安全性的身分驗證設備。部分低安全性卡片的 UID 可能被複製，因此不建議直接將這套設備用於門禁、金流或需要嚴格防偽的場合。

此外，自製打卡鐘若要作為正式薪資或勞動出勤依據，仍應建立定期備份、資料覆核及異常補登流程，避免只依賴單一設備。

## 完成後的心得

從最初只有 ESP32、RC522 和蜂鳴器的小實驗，逐步加入 Web 管理、四種打卡模式、DS3231、Excel 匯出、備註、備份與離線使用後，這台設備已經不只是簡單的讀卡器，而是一套可以實際投入日常使用的小型出勤管理系統。

DIY 最大的優點，不只是節省購買商用設備的費用，而是所有功能都能依照自己的需求調整。未來如果需要增加外接燈號、顯示器、MQTT、Home Assistant 自動化或更多統計功能，也可以繼續在現有架構上擴充。

這次製作過程也讓我體會到：做出「能讀卡」並不難，真正需要花時間的，是讓資料不會消失、時間永遠正確、操作足夠直覺，而且出現問題時，一般使用者知道該怎麼處理。

當這些細節都完成後，一個原本只是桌面上的 ESP32 實驗，就真的能成為每天穩定使用的產品。
