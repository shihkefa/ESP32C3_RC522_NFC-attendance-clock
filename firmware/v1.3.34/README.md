# ESPHome 四按鍵 NFC 打卡鐘 v1.3.34（RC522／ESP32-C3）

本版提供四種打卡模式、員工與卡片管理、管理員補打卡、每日備註、Excel 工時彙總及 JSON 備份還原，可獨立運作，不依賴 Home Assistant。

## v1.3.34 功能

「刷卡紀錄 → 管理員補打卡」可選員工、日期時間與上班／下班／加班上班／加班下班，核對管理員密碼後新增紀錄。時間以裝置 UTC+8 為準，僅接受最近兩個日曆月內且不晚於裝置目前時間的紀錄；還原期間或時間無效時暫停補登。補登會納入 Excel 工時及 JSON 備份，沿用上班取最早、下班取最晚規則，不取代原有紀錄。每筆紀錄為 32 bytes，使用寫入序號定位下一筆資料。

四種模式可各自啟用並設定每天的自動切換時間，已啟用的模式不可設定相同時間，支援跨午夜排程。預設每天 `00:00` 切換上班、`14:00` 切換下班；加班上班與加班下班排程預設關閉，建議時間為 `18:00` 與 `22:00`。設定需核對管理員密碼，保存後斷電仍保留。

管理頁分為「總覽、刷卡紀錄、員工管理、請假／備註、系統設定、使用說明」六個分頁。總覽顯示最近 10 筆刷卡資料，刷卡紀錄、員工與備註每頁顯示 20 筆並提供搜尋。最多管理 100 位員工及 500 筆每日備註。

Excel 提供 10 個欄位，包含「當日出勤工時」與「當日加班工時」，依同一天的上下班配對計算，使用 `[h]:mm` 格式；缺少成對時間時，工時欄位保持空白。每位員工另有獨立分頁。

開機先讀取 DS3231 備用時鐘，連網後以 SNTP 自動校時。時間來源依序為中國 `0.cn.pool.ntp.org`、台灣 `0.tw.pool.ntp.org` 與新加坡 `0.sg.pool.ntp.org`；校時成功後更新已連接的 DS3231。Wi-Fi 取得 IP 後立即嘗試校時，時間仍無效時在 10 秒及 30 秒重試，成功後每小時校時。Home Assistant 可顯示診斷狀態，不作為時間來源。

登入管理頁與新增／刪除員工、清除紀錄、手動校時等敏感操作共用同一組密碼；修改後兩者會同步生效並保存於非揮發性記憶體，斷電重啟不會還原。完整 JSON 備份包含員工、卡號綁定、每日備註與刷卡紀錄，但不包含任何密碼或 secrets。

每日請假／備註容量為 500 筆，每筆最多 15 個字。4MB Flash 使用獨立的 56 KiB `att_notes` 分割區，採兩個 28 KiB 備援槽交替寫入。員工與備註採雙槽交替寫入並校驗；管理頁與匯出每批讀取 50 筆備註，以降低記憶體用量。

管理頁面固定網址為 `http://nfc-attendance-clock.local/attendance/`，也可使用 `http://裝置IP/attendance/`。

功能：員工新增/停用、掃卡綁定、上班/下班打卡、最近兩個日曆月紀錄、Excel XLSX 彙總匯出，以及不依賴 Home Assistant 的獨立運作。管理頁頂部會每 5 秒更新裝置目前時間、網路連線狀態、Wi-Fi 名稱與 IP 位址。

## 安裝

從本資料夾複製以下 **5 個程式檔**到 ESPHome 設定資料夾，保留相對路徑：

```text
ESPHome 設定資料夾/（Home Assistant 通常為 /config/esphome/）
├── nfc-attendance-clock.yaml
├── attendance_partitions.csv
└── components/
    └── attendance_web/
        ├── __init__.py
        ├── attendance_web.h
        └── attendance_web.cpp
```

1. 首次使用時，將 `secrets.example.yaml` 複製為同層的 `secrets.yaml`，填入 `wifi_ssid`、`wifi_password`、`attendance_web_password`。已有 `secrets.yaml` 時保留原檔，只補齊缺少的項目。
2. 依下方接線表核對硬體，在 ESPHome 驗證並編譯 `nfc-attendance-clock.yaml`。
3. 新裝置下載 Factory 格式韌體，透過 CH340 USB 與 [ESPHome Web](https://web.esphome.io/) 安裝。已有資料的裝置先下載完整 JSON 備份，再依 [OTA 安裝說明](./OTA更新說明.md)選擇 USB 或 OTA。
4. 開啟管理頁，帳號為 `admin`，自行編譯的初始密碼由 `attendance_web_password` 設定，之後可在管理頁修改。

也可從 [GitHub 專案首頁](https://github.com/shihkefa/ESP32C3_RC522_NFC-attendance-clock)下載 v1.3.34 公開 Factory BIN，免自行編譯。公開 BIN 使用熱點 `NFC-Clock-Fallback`、熱點密碼 `change-me-1234` 配網，初始管理員密碼為 `change-me-1334`，首次登入後請修改。完整檔案複製及燒錄步驟見 [ESPHome 燒錄教學](https://github.com/shihkefa/ESP32C3_RC522_NFC-attendance-clock/blob/main/docs/ESPHOME_FLASHING.md)。

若將外部元件合併至既有 YAML，請保留 `wifi.id: wifi_component`，並在 `attendance_web:` 下加入 `wifi_id: wifi_component`、`hardware_rtc_id: hardware_rtc` 與 `admin_password: !secret attendance_web_password`。`web_server.auth.password` 與 `attendance_web.admin_password` 必須引用同一個 secret，讓第一次啟動時的登入密碼及操作核實密碼一致。

## mDNS 固定網址

YAML 已明確啟用 mDNS。電腦或手機與打卡鐘在同一個區域網路時，即使 DHCP 配發的 IP 改變，仍可使用 `http://nfc-attendance-clock.local/attendance/`。若路由器、VLAN 或 Wi-Fi 設定阻擋 multicast/mDNS，請改用裝置目前 IP。

## 操作

### Home Assistant 實體

- `最後校時時間 LAST_SYNC`、`目前校時來源 TIME_SOURCE`：顯示本次開機最後一次 SNTP 或管理員手動校時的時間與來源；若只從 DS3231 讀取，來源會顯示 DS3231。
- `最後刷卡資訊 LAST_CARD`：顯示「時間｜姓名｜卡號｜結果」，只記錄刷卡／綁卡事件，不會被切換模式或一般管理操作覆蓋；另有 `LAST_CARD_EMPLOYEE`、`LAST_CARD_UID`、`LAST_CARD_RESULT` 三個獨立實體，方便 HA 儀表板與自動化使用。
- `打卡模式 ATTENDANCE_MODE`：顯示並切換上班、下班、加班上班或加班下班模式。
- `立即同步時間 SYNC_NOW`：立即重新啟動 SNTP；管理員手動校時優先期間不會覆蓋手動時間。
- `打卡鐘時間有效 TIME_VALID`、`DS3231連線 RTC_CONNECTED`、`打卡鐘網路 ONLINE`：提供 HA 自動化使用的診斷狀態。

- 新增員工後按「綁定下一張卡」，再感應卡片。
- 管理頁的「管理員密碼」可同步修改登入密碼及所有敏感操作的核實密碼。新密碼須為 8～64 個半形英文字母、數字或符號且不可含空白；修改成功後瀏覽器會要求使用新密碼重新登入，帳號仍為 `admin`。
- 管理頁的「資料備份與還原」可下載 JSON 完整備份。備份包含有效員工的工號、姓名、卡號綁定、所有已保存的每日備註，以及目前兩個月範圍內的刷卡紀錄；不包含管理密碼、Wi-Fi 密碼、API／OTA 金鑰或其他 secrets。
- 匯入備份前必須輸入目前管理密碼並確認。匯入會先清除裝置內現有員工、備註及刷卡紀錄，再分批寫入備份資料；過程中會暫停刷卡。請保持供電與同一個管理頁面開啟，直到顯示「還原完成」。
- 新增、更新或刪除員工時，先在員工管理區輸入管理頁密碼。密碼會送至 ESP32 核對，無論從網頁或直接呼叫 API，密碼錯誤都不會變更員工資料。
- 同一卡號只能綁定一位有效員工。若綁定其他員工已使用的卡片，蜂鳴器會連叫三聲，管理頁顯示原綁定工號與姓名，且不會改動任何員工資料；同一員工重刷自己的原卡只會確認既有綁定，不會再次寫入 Flash。
- 若員工資料中存在重複卡號，系統不會自行刪除任何一方。請在員工列表確認相同卡號，將其中一位重新綁定另一張卡，或刪除不需要的員工。
- 工號比對不區分英文字母大小寫，例如 `A001` 與 `a001` 視為同一工號。管理頁以既有工號再次新增時會更新該員工，而不會建立第二筆。
- 板載 GPIO8 狀態燈統一使用 65% 亮度：一般上班為綠燈、一般下班為紅燈、加班上班為濃郁暖黃色恆亮、加班下班為藍燈恆亮；等待綁定新卡時依序循環紅、橙、黃、綠、青、藍、紫，綁定完成後自動恢復目前模式顏色。
- Wi-Fi 尚未連線或連線中斷時，GPIO8 以橘燈每 0.5 秒閃爍；恢復連線後自動回復原本模式顏色。只要 DS3231 內的時間有效，完全離線開機仍可刷卡並保存到本機 Flash。
- Wi-Fi 與 API 的自動重啟逾時已設為 `0s`，避免無路由器或無 Home Assistant 時每隔一段時間重啟打卡鐘。
- 按 GPIO0 後持續為上班刷卡模式，按 GPIO1 後持續為下班刷卡模式，直到再次切換。
- 按 GPIO2 後持續為加班上班模式，按 GPIO10 後持續為加班下班模式。GPIO2 是 ESP32-C3 的啟動取樣腳位，請勿在通電或重新啟動瞬間持續按住此按鍵。
- 管理頁可遠端切換一般上下班或加班上下班模式。自動切換啟用時，手動選擇會維持到下一個已啟用的自訂排程時間；關閉自動切換後則會一直維持，直到再次由實體按鍵、管理網頁或 Home Assistant 變更。
- 「系統設定 → 自動模式切換」可分別啟用上班、下班、加班上班與加班下班排程，並各自設定每天的切換時間，也可關閉全部自動切換。設定會保存於 ESP32，修改時需輸入管理員密碼。
- 開機先讀取 DS3231；若 RTC 與 SNTP 均未提供有效時間，才會拒絕打卡，以免留下錯誤紀錄。
- 管理頁的「管理員時間校正」可設定手動時間；核對管理密碼後，時間會寫入 DS3231，且本次開機期間優先於 SNTP。按「恢復網路自動校時」或重新啟動裝置後，會重新接受 SNTP 時間。
- Excel 第一個分頁為「出勤彙總」，欄位依序為日期、工號、姓名、上班打卡時間、下班打卡時間、加班上班時間、加班下班時間、備註、當日出勤工時、當日加班工時；每位員工另有一個以 `工號_姓名` 命名的獨立分頁。
- 管理頁的「每日請假／備註」只接受管理員手動輸入，可依員工與日期新增、修改或刪除。每筆最多 15 個字、近期最多 500 筆；即使當天完全沒有刷卡，只要有手動備註，Excel 仍會產生該員該日的一列並在「備註」欄顯示內容。
- 員工刪除後，其原有每日備註仍會保留並顯示為「已刪除員工（槽位 N）」，管理員可直接從備註列表將它刪除；已刪除員工不能再新增或修改備註。
- 「刪除所有刷卡紀錄」會先顯示不可復原警告，再要求重新輸入管理頁密碼；密碼由 ESP32 核對成功後才會清除刷卡紀錄區，不會刪除已登記的員工與卡片。
- 同一人同一天重複刷卡時，上班取最早一筆，下班取最晚一筆。
- 蜂鳴器一聲代表綁卡或打卡確實成功；未登記、時間未同步或 Flash 寫入失敗時為三聲，原因會顯示在管理頁。

## 忘記管理員密碼時

網頁修改後的密碼會保存在 ESP32 的 NVS，採保留 NVS 的 OTA 更新時仍會沿用；Factory 完整安裝可能重設配網與初始密碼。若已忘記密碼，請先確認手邊有先前匯出的完整 JSON 備份，再以 USB 清除整顆 Flash 並重新刷入本版韌體。之後使用自行編譯時設定的 `attendance_web_password` 登入；公開 BIN 的初始密碼為 `change-me-1334`。從管理頁匯入備份即可恢復員工、卡號、備註及刷卡紀錄。完整清除前若沒有備份，裝置內資料將無法復原。

## 容量與保存

專用 `attendance` Flash 分割區為 840 KiB，其中 24 KiB 用於兩份員工資料備援。刷卡環形區在約 99% 水位循環，容量為 25,856 筆；另有 56 KiB `att_notes` 分割區，使用兩份 28 KiB 備援槽保存最多 500 筆管理員手動備註。4MB 位址空間已全部分配，但程式區、資料區與備援區彼此固定，不會因某區寫滿而侵入其他區域。

網頁、CSV、Excel 與 JSON 備份僅提供目前日期往前兩個日曆月內的刷卡資料；過期資料會被視為可淘汰資料，環形區到達 99% 水位後由新紀錄依序覆蓋最舊紀錄。這種作法不需要每天搬移整個資料區，可降低 RAM 峰值、Flash 擦寫次數及刷卡期間的阻塞風險。以 100 人每天四次刷卡計算，25,856 筆約可保存 64 天；大量重複刷卡仍可能讓兩個月內的最舊紀錄提早被覆蓋。

## 接線

RC522：SCK GPIO4、MISO GPIO5、MOSI GPIO6、SS/SDA GPIO7、3.3V、GND；`RST` 接 3.3V，不接 GPIO10。GPIO10 用於加班下班按鍵。

按鍵均採一端接 GPIO、另一端接 GND：GPIO0（一般上班）、GPIO1（一般下班）、GPIO2（加班上班）、GPIO10（加班下班）。有源蜂鳴器 SIG→GPIO3、VCC→3.3V、GND→GND。板載 WS2812 使用 GPIO8。

DS3231：VCC→3.3V、GND→GND、SDA→GPIO18、SCL→GPIO19；SQW 與 32K 不接。模組只能使用 3.3V 供電，避免 I²C 上拉到 5V，也不要讓藍板上的充電電路以 5V 對不可充電的 CR2032 充電。正常 I²C 掃描會看到 DS3231 的 `0x68` 與板載 AT24C32 的 `0x57`。

本板使用 CH340 進行 USB 燒錄，因此 YAML 將 Logger 改到 UART0，釋放 ESP32-C3 的 GPIO18／19 作為 I²C。刷入本版後，GPIO18／19 不再提供原生 USB Serial/JTAG 功能，但板載 CH340 的 USB 燒錄與序列日誌仍可使用。
